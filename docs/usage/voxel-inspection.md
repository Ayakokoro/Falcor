# 孤立体素与 GPU 裁剪面片对比

在 `RayMarchingPass` 加载体素文件以及对应的原始场景后：

1. 开启 **Debug**，点击画面中的体素。面板会显示节点最小格坐标、节点尺寸和数据索引。
2. 如需检查粗层级，先调整 **Forced LOD** 再选取。裁剪范围使用实际命中的整个节点。
3. 勾选 **Inspect isolated node**。左侧是烘焙体素的椭球与材质，右侧是原始场景经过 GPU 裁剪的面片。
4. 左键拖动同步旋转两边的检查视角，滚轮缩放。也可以使用 Orbit 滑条。取消勾选返回主场景。

检查器使用独立方向光，两边共享视角、光照和输出色调映射，不考虑节点以外的遮挡、场景灯光和间接光。检查相机不会修改场景相机。

`Inspector view` 可选着色、法线、漫反射颜色和线框/轮廓。`Inspector coverage` 控制体素的覆盖率，`Inspector internal visibility / local shadows` 控制体素的内部可见性和参考面片之间的局部阴影。可见材质沿用主面板选择的内部可见性模式。

参考面片使用原场景的 Standard 材质参数、贴图、法线贴图，以及与体素相同的 Frostbite/GGX 着色模型。当前针对不透明三角形表面，不处理透明度、透射、自发光或位移；其他材质类型显示洋红色，非三角形几何不参与裁剪。`Reference texture LOD` 可以调整参考贴图的采样层级，默认 0；逐点采样与烘焙时面积平均的纹理过滤结果可能不同。

原始场景必须与烘焙时的坐标、实例变换、动画时刻和材质一致。加载 `.pyscene` 后的材质覆盖不会追溯修改已烘焙的体素文件。

## GPU 裁剪与缓存

`ClipInspector.cs.slang` 从当前场景的 GPU 几何读取每个三角形实例，应用实例变换，再调用现有 `VoxelizationUtility.slang` 的六平面裁剪逻辑。裁剪结果保留原三角形的重心坐标以恢复材质属性，随后在 GPU 上生成三角扇。过程不使用 CPU 裁剪或 CPU 烘焙中间面片。

检查器使用独立的临时面片格式，保留裁剪函数的完整顶点结果，不受旧 `Polygon` 六顶点存储上限限制。参考缓冲最多容纳 4096 个生成三角形；超限时整个比较图显示洋红色，并提示选择更细的节点，避免展示被截断的参考结果。

选中节点后锁定选取，只在切换节点、场景几何变化或点击 **Reclip selected node** 时重新裁剪。旋转检查视角复用缓存。参考图像通过射线与缓存面片相交生成，适用于少量面片的单节点调试。

## CPU 同步

关闭 Debug 时，不执行选取缓冲的 CPU 拷贝、映射和对应的 `submit(true)`，也不拦截场景选取鼠标事件。开启 Debug 并查看主场景时，每帧回读一次选中节点信息；NDF 和孤立节点视图锁定选取，不重复回读。GPU 裁剪统计只在重裁剪时回读。
